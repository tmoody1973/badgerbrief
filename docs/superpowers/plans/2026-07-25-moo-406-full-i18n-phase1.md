# MOO-406 Full-site i18n — Phase 1 (Foundation & Static Pages) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the i18n foundation — locale primitives, a twin-aware language toggle, locale-aware chrome (Spanish nav/footer on `/es/*`), a machine-translation disclaimer banner, and Spanish `/es`, `/es/about`, `/es/methodology` — without touching English URLs, English output, or static rendering.

**Architecture:** English stays at the root, unchanged. Spanish lives under `/es/*` as thin per-locale routes rendering shared components with an ES dict — the `/es/vote` pattern generalized. Chrome is locale-aware via a client component reading `usePathname()` (server-renders the right language per route, so static generation is preserved). No `app/[lang]` restructure, no route-group move.

**Tech Stack:** Next 16 App Router (static/ISR), React, Tailwind v4, vitest.

## Global Constraints

- **English is untouched:** every English URL, canonical, and the rendered EN nav/footer content stay exactly as they are. The static-cache posture (`cache-control: public`, `x-vercel-cache: HIT`) must not regress.
- **Static rendering preserved:** no page may become dynamic. Chrome reads `usePathname()` as a CLIENT component (server-rendered per route) — do NOT read `headers()`/`cookies()` in any page or layout for locale.
- **No route moves:** English route files stay where they are. Spanish routes are NEW files under `src/app/es/`.
- **Rollout-safe links:** the toggle and hreflang only offer Spanish for paths that HAVE a twin (`TRANSLATED_PATHS`); never link to a not-yet-built `/es/*`.
- **Hand-translated content is Tarik-verified** before deploy (the About disclosure is sensitive — Radio Milwaukee / Plan Commission). Direct quotes: none on these static pages, so N/A this phase.
- **`<html lang>` stays `en`** at the root; ES pages mark content-level `lang="es"` (as `/es/vote` does) and set `documentElement.lang="es"` at runtime. Perfect per-route `<html lang>` = Phase 3.
- **Test command:** `npx vitest run <file>`.

- [ ] **Step 3: Create `src/lib/i18n/locale.ts`**

```ts
export type Locale = "en" | "es";

export const TRANSLATED_PATHS = new Set<string>(["/", "/vote", "/about", "/methodology"]);

export function esTwin(enPath: string): string {
  return enPath === "/" ? "/es" : `/es${enPath}`;
}

export function enTwin(esPath: string): string {
  if (esPath === "/es") return "/";
  return esPath.replace(/^\/es/, "") || "/";
}

export function hreflangFor(enPath: string) {
  return { en: enPath, es: esTwin(enPath), "x-default": enPath } as const;
}
```

```ts
import { TRANSLATED_PATHS, enTwin, esTwin } from "@/lib/i18n/locale";

export function langToggleFor(pathname: string): { label: string; href: string } {
  if (pathname === "/es" || pathname.startsWith("/es/")) {
    return { label: "English", href: enTwin(pathname) };
  }
  // English side: only offer the direct twin when it exists; else the Spanish home.
  const href = TRANSLATED_PATHS.has(pathname) ? esTwin(pathname) : "/es";
  return { label: "Español", href };
}
```
